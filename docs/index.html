これは何か

あちこちの tmux セッション / ウィンドウ / ペインで Claude Code を同時に走らせていると、「いまどれが入力待ちで、どれが作業中で、何をやっていたか」を見失いがち。ccux は全ペインを走査して claude が動いているペインだけを集め、各セッションのステータスとrecap（要約）を fzf で一覧プレビューし、選んだセッションが開いているペインへ tmux で移動します。

ccux — popup (prefix C-j)
Claude Sessions > █ STATUS PROJECT BRANCH CTX RECAP ▶ ▲ Waiting my-repo main Implement feature A ▲ Waiting my-service develop 0% Fix bug B … Working my-thing master 16% Refactor module C … Working scratchpad main 14% Explore idea D ● Idle my-notes feat/nav Write docs E ┌─ preview ─────────────────────────┐ │ ▲ Waiting my-repo │ │ branch main pane my-repo:0.1 │ │ ▌ Implement feature A │ │ you › Which option should I use? │ │ claude › Done — added it + tests. │ │ ──── live pane ──── │ └───────────────────────────────────┘

インストール

go install github.com/2357gi/ccux/cmd/ccux@latest
# または clone して
make install        # go install ./cmd/ccux  ( -> $GOPATH/bin )

前提: fzf と tmux。バイナリは ~/go/bin/ccux（PATH 上）に入ります。

tmux からポップアップで呼ぶ

~/.tmux.conf:

bind-key -T prefix C-j display-popup -w 90% -h 80% -E "exec ccux"

prefix C-j でフローティングポップアップが開き、選択するとそのペインへ飛びます。

ステータスの種類

ステータスは tmux capture-pane で取得したペインの表示内容から判定します。種類は次の4つ。注意が必要なもの（Waiting → Working → Idle → Active）の順に並びます。

表示意味判定根拠（ペイン内テキスト）
▲Waitingあなたの操作待ち。承認プロンプトや確認待ちで止まっている。最優先で表示。❯ 1. のような選択肢 / (y/n) / 「Do you want to…」＋番号付き選択肢
…Working実行中・思考中。ツール実行や推論で動いている。esc to interrupt の表示、またはスピナー（✽ ⠋ ⠙ ⠹ …）
●Idle入力待ち。空のプロンプト枠が出ていて、あなたが打つのを待っている。空の入力行 │ > / ❯ だけの行
○Active不明／その他。上のどれにも一致しない時のフォールバック。（該当シグナルなし）

あわせて context 残量 %（auto-compact までの残り）もペイン表示から拾って列に出します。

ステータスの鮮度（"遅い" の正体）

結論：データ取得そのものは速い（実測 約0.2秒）。"遅い" と感じるのは fzf を開いている間、一覧が起動時のスナップショットのまま固定されるためです。fzf には定期リロード機能が無いので、ccux は以下の設計にしています。

鮮度のルール
  • 一覧（STATUS列）：fzf 起動時の一回ぶんのスナップショット。C-r で再取得して最新化できます。
  • プレビュー（右ペイン）：選択を動かすたびに ccux preview を再実行するので、recap も「live pane」も常に最新です。
  • 再実行：ccux / ccux list を実行するたびに全ペインを取り直すのでキャッシュ無し＝そのときの状態が出ます。

つまり「いまの状態を確実に見たい」ときは、対象セッションにカーソルを合わせてプレビューを見るか、C-r を押せば最新になります。

recap（要約）の中身

プレビューには、そのセッションのトランスクリプト（~/.claude/projects/…/<session>.jsonl）から抽出した要約を表示します。

▌ タイトル

Claude が自動生成したセッションタイトル（ai-title）。最良の1行要約。未生成なら直近プロンプトで代替。

you ›

あなたが最後に打ったプロンプト（ツール結果は除外）。

claude ›

Claude の最後のテキスト応答。

──── live pane ────

そのペインの現在の表示内容の末尾。最新の生の状況。

仕組み・データフロー

tmux list-panes ──┐
                  ├─→ 各ペイン (id %9, cwd, activity)
ps -axo comm ─────┘        │
   claude プロセス抽出      │ TMUX_PANE 環境変数で
   (pgrepは取りこぼす)      │ ペイン⇔claudeを一意対応
                          ▼
            ┌─ claude が動くペインだけ ─┐
            │                          │
   capture-pane           cwd → ~/.claude/projects/<encoded>/
   → status 判定          → 最新 *.jsonl → ai-title/最後のprompt/応答
            │                          │
            └────────→ Session ←───────┘
                         │ Waiting→Working→Idle 順にソート
                         ▼
                  fzf 一覧 + preview ──Enter──→ tmux switch-client
                                                 select-window / select-pane
  • ペイン⇔セッション対応：各 claude プロセスの環境変数 TMUX_PANE（例 %9）を ps -E から読み、tmux ペインと一意に対応づけ（同一 cwd に複数 claude がいても曖昧さなし）。
  • claude の検出：ps -axo comm で実行ファイル名が claude のものを拾う。pgrep -x claude は genuine な claude を取りこぼすことがあるため不使用。また tmux 上では claude のコマンド名がバージョン番号（2.1.169 等）に化けるので、コマンド名一致では検出できない。
  • recap の特定：cwd を ~/.claude/projects/<英数字以外を - に置換> に変換してトランスクリプトを探す。
  • 複数セッションの振り分け：同一 cwd に複数 claude がある場合、ペインの最終アクティビティ時刻とファイル更新時刻で対応づける。

制限・既知の挙動

  • recap はベストエフォート：同一 cwd で複数の claude を走らせている場合、どのトランスクリプトがどのペインか厳密には断定できないため、アクティビティ時刻で推定します（ステータスとペイン移動は常に正確）。
  • 新規セッション：ai-title がまだ生成されていないと、タイトルの代わりに「最後のプロンプト」を表示します。
  • ステータスは推定：ペインの表示テキストからのヒューリスティック判定。カスタムテーマや特殊な表示では外すことがあります。
  • tmux 内の claude のみ：TMUX_PANE を持つ＝tmux ペインで起動した claude が対象。tmux 外の claude は出ません。

開発（TDD構成）

ccux/
├── cmd/ccux/main.go        # CLI・fzf連携・表示整形・表示幅(CJK)処理
└── internal/
    ├── tmux/               # list-panes 解析 / capture / jump
    ├── proc/               # ps から claude検出 + TMUX_PANE 抽出
    ├── status/             # capture-pane → ステータス判定 / context%
    ├── transcript/         # cwd→projectsパス / jsonl から recap 抽出
    └── session/            # 上記を統合・cwd別にtranscript振り分け

パース・判定・対応づけといったロジックを純粋関数に寄せ、各パッケージに単体テストを置いています。
